# MEMORY.md

Project notes and conventions for anyone — human or otherwise — working in this
repository. Read this before changing anything.

## Project

TruckFlow — a multi-tenant trucking management system (TMS). Two halves that are **not yet wired together**: a Vite/React/TypeScript frontend and a FastAPI/SQLAlchemy backend. See "Frontend/backend split" below before assuming any view talks to the API.

## Commands

Frontend (repo root):

```bash
npm run dev
```

```bash
npm run build
```

`build` runs `tsc` then `vite build` — it is the typecheck gate. For a typecheck without emitting, `npx tsc --noEmit`.

`npm run lint` is declared in `package.json` but **there is no ESLint config and ESLint is not installed** — it fails. Don't cite it as a passing check; use `tsc` instead.

Backend:

```bash
.venv/Scripts/python main.py
```

Serves on `:8000` with reload; docs at `/docs`, health at `/api/v1/health`. `main.py` calls `Base.metadata.create_all()` and `seed_default_data()` at import time, so the SQLite file is created and seeded on first run — there are no migrations. Deleting `nune_express_tms.db` is the reset. Config comes from `.env` (see `.env.example`); it defaults to SQLite so no Postgres is needed.

Seeded logins: `admin`/`admin123`, `marcus`/`dispatcher123`, `dmiller`/`driver123` (the last one expires in 4 days on purpose, to exercise the expiry banner).

There is no test suite in either half.

## Frontend/backend split

The frontend reads and writes **`src/services/mockStore.ts`**, a singleton class backed by `localStorage` with simulated latency (`simulatedLatencyMs`) and an optional `simulateErrors` flag. Every view receives data as props from `App.tsx`, which holds all entity state and passes `onReload` down; mutations call `mockStore`, which notifies subscribers and re-triggers `reloadData()`. There is no router — navigation is the `activeTab` state in `App.tsx` switching between nine sections.

The only real network call in `src/` is the login `fetch` in `AuthContext.tsx`, which hits `http://localhost:8000/api/v1/auth/login` and **falls back to mock auth silently if the backend is down**. So the app works fully standalone, and a broken backend looks like a working login.

The backend (`app/`) is a complete JWT/RBAC API — `app/api/v1/{auth,users,loads,drivers,fleet,customers,invoices}.py` over `app/models.py` — that the UI does not consume. When adding a feature, decide deliberately which half you're changing; they do not share types (`src/types/tms.ts` is camelCase TS, `app/schemas.py` is snake_case Pydantic).

`app/models.py` is generated by `generate_models.py` (a script that writes the file from an embedded string). Edits to `app/models.py` are lost if that script is re-run.

## Design system (the load-bearing convention)

`src/styles/index.css` defines semantic tokens as **space-separated RGB channels** on `:root` and `.dark`; `tailwind.config.js` maps each to `rgb(var(--token) / <alpha-value>)`. Components therefore write `bg-surface text-fg border-bd` and get both themes for free.

Two rules the whole redesign depends on:

- **No `dark:` variants in components.** Theme drift was the original bug; the token layer makes it structurally impossible. If a color needs to differ by theme, add or change a token, never a `dark:` class.
- **No raw Tailwind palette colors** (`bg-slate-900`, `text-gray-500`, hex literals) in components. Exceptions are deliberate and documented in place: the Sidebar and LoginView are theme-invariant navy/gradient surfaces.

Both are easy to grep for and worth checking before committing UI work.

Other token facts that are non-obvious:

- `--fg-3` is tuned to clear **4.5:1** contrast, not 3:1 — the muted tier carries real content at 10.5–11.5px, so the large-text allowance doesn't apply. Light mode's worst case is `--surface`; dark mode's worst case is `--surface-2` (it is the *lighter* of the two there). Changing `--fg-3` means re-checking both.
- `--hero-bg` / `--on-hero` are their own tokens rather than derived from `--accent`, because accent flips to a light blue in dark mode.
- The sidebar has its own `--side-*` scale and deepens in dark mode so the rail still recedes below `--canvas`.
- Shadow tokens are exposed as `shadow-btn` / `shadow-hero`, not `shadow-accent` — that name would collide with the shadow-*color* utility.

Primitives live in `src/components/ui/` and are re-exported from `src/components/ui/index.ts`; import from there. Views compose `PageHeader`, `Card`, `StatCard`, `DataTable`, `FilterBar`, `Modal`, `Badge`, `EmptyState` rather than hand-rolling markup. `Badge.statusTone()` is the single mapping from any domain status string to a visual tone — extend it there, not at call sites.

`Modal` implements the full dialog pattern (focus trap, initial focus, focus restore, `aria-labelledby`); build new dialogs on it instead of a bare overlay. Toasts are the app's only confirmation channel and live in an `aria-live` region — errors get `role="alert"`, everything else `role="status"`.

The sidebar collapses to a 56px icon rail. `App.tsx` owns the `collapsed` flag (persisted to `localStorage` under `nune_tms_sidebar_collapsed` and read synchronously at mount, so a collapsed reload doesn't flash open) because the toggle lives in `Header` and the panel is its sibling. The rail's paddings are picked so an icon centre lands ~28px from the panel edge in **both** states — that is what keeps the icons still while the width animates, so re-check the arithmetic before changing any of them.

Paginated views (Loads, Billing, Customers, Drivers, Fleet, Settings→Users) all clamp the current page: `const page = Math.min(currentPage, totalPages)`. Without it a shrinking result set strands the user on an empty page with the pager hidden. Any new paginated list needs the same clamp, and every filter control needs to reset to page 1.

## Standing constraints

These predate the current code and still hold:

- The nine navigation sections and their order do not change.
- The shapes in `types/tms.ts`, `mockData.ts`, and `mockStore.ts` do not change.
- Application behavior does not change — UI work is presentation only.
- Light is the default theme.
